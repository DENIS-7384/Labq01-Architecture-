## Контрольные вопросы

1. **Почему программа может узнать имя компьютера, хотя вы не писали его в коде?**
   Потому что имя хранится в операционной системе. Программа запрашивает
   его через класс Environment, а .NET обращается к ОС, которая возвращает
   актуальное значение во время выполнения.

2. **Какую роль играет ОС, когда программа запрашивает у неё сведения?**
   ОС — посредник между программой и оборудованием. Она хранит сведения
   о компьютере, управляет доступом к CPU, памяти и файлам и предоставляет
   программе запрошенные данные.

3. **Что означает «64-битная ОС»?**
   ОС использует 64-битную архитектуру и может адресовать гораздо больше
   памяти (теоретически до 2^64 байт адресного пространства), чем 32-битная.

4. **Что показывает Environment.ProcessorCount и обязательно ли это число
   совпадает с числом физических ядер?**
   Показывает число логических процессоров, видимых ОС. С числом физических
   ядер совпадает не всегда: при Hyper-Threading логических обычно в 2 раза
   больше.

5. **Чем память процесса (WorkingSet) отличается от всей оперативной памяти
   компьютера?**
   WorkingSet — объём физической памяти, занятый конкретным процессом.
   Оперативная память компьютера — общий ресурс, разделяемый всеми
   процессами и ОС.

6. **Почему одна и та же программа без изменений в коде может показать
   разные результаты на разных компьютерах?**
   Потому что данные берутся из ОС и оборудования конкретного компьютера
   во время выполнения: разное имя, версия ОС, число процессоров, объём
   памяти. Код одинаковый — среда разная.

## Итоговый вывод

- Программа не «знает» ничего заранее — она спрашивает у ОС через .NET
  в момент выполнения.
- ОС выступает посредником: она хранит сведения о железе и выдаёт их
  по запросу программы.
- Память процесса — это часть оперативной памяти, выделенная конкретной
  программе, а не вся память компьютера.
- Одинаковый код на разных компьютерах даёт разные результаты, потому
  что среда выполнения (ОС, процессор, память) у них разная.
- Связь «программа → .NET → ОС → оборудование» объясняет, откуда берутся
  все получаемые значения.

## Дополнительное задание. Мини-монитор системы

### Что делает программа
Получает объект текущего процесса через `Process.GetCurrentProcess()`,
выводит его имя и PID, затем трижды измеряет WorkingSet64 с паузой
на Enter между измерениями.

### Что нового я узнал о классе Process
`Process.GetCurrentProcess()` возвращает объект, представляющий именно
мой процесс. Через него можно получить PID (`Id`) и память (`WorkingSet64`),
а `Refresh()` обновляет данные перед новым измерением.

### Сравнение памяти программы и Диспетчера задач
Значения близки, но отличаются на несколько МБ — Диспетчер задач и .NET
считают память немного по-разному (например, включают/исключают
разделяемые страницы).

### Почему значение памяти может немного изменяться
Во время работы программа выделяет и освобождает объекты, работает
сборщик мусора .NET, загружаются служебные библиотеки — поэтому объём
занятой памяти не обязан быть постоянным между измерениями.
